EDM Zone · Quoting automation

Connecting the quoting app to the sales mailbox

Everything else is built and working. This is the one remaining job: giving the app permission to read sales@edmzone.co.uk on its own, so that an email categorised RFQ becomes a priced draft quote without anybody doing anything.

Part 1 is for Roger and takes about two minutes. Part 2 is for whoever looks after EDM Zone's Microsoft 365 and takes about twenty.

PART 1

What Roger does

You

Two things, both small. Neither needs anyone technical.

  1. Make the RFQ category in the sales mailbox

    In Outlook, open the sales@edmzone.co.uk mailbox — not your own. Right-click any message, choose Categorise, then All Categories, then New. Name it exactly:

    RFQ

    Three capital letters, nothing else. No trailing space. The app compares the name exactly, so Rfq or RFQ  would silently never match — mail would arrive and nothing would happen.

    It has to be created while you are in the sales mailbox. Categories belong to a mailbox, so one made in your own Outlook lands on your list, not the shared one.

  2. Send Part 2 of this page to your IT person

    Everything they need is below, including the values specific to EDM Zone. They do not need to understand the quoting app — only to create a login for it and lock it to the one mailbox.

    When they are done, they send you back two ID numbers and one password. Read the box at the end of Part 2 before you pass those on to me — the password in particular must not be typed into a chat or an email.

What this does and does not allow

The app will be able to read the sales mailbox and write draft replies into it. That is all.

It is not being given permission to send email. That is deliberate and it is enforced by Microsoft, not by a setting inside the app: without the send permission, a quote physically cannot leave the building without a person opening the draft and pressing send.

PART 2

What the IT administrator does

Your M365 admin

This registers an application identity in Entra ID, gives it Microsoft Graph mail permissions, and — importantly — restricts those permissions to a single mailbox. You will need Global Administrator (or Application Administrator plus Exchange Administrator) and about twenty minutes.

  1. Register the application

    entra.microsoft.com → Applications → App registrations → New registration

    Name it EDM Zone Quoting. For supported account types choose Accounts in this organizational directory only. Leave the redirect URI blank — this is a daemon using client credentials, there is no interactive sign-in. Click Register.

    From the overview page that appears, copy the Application (client) ID and the Directory (tenant) ID.

  2. Create a client secret

    Certificates & secrets → Client secrets → New client secret

    Describe it Quoting app and set an expiry — 24 months is reasonable. Whatever you choose, diary the expiry date: when a secret expires the app stops reading mail, and the only symptom is that nothing appears in the quoting queue.

    The step people get wrong

    Azure shows both a Value and a Secret ID. You need the Value. It is displayed once, on this screen, and can never be retrieved again — navigate away and you must delete the secret and make another.

  3. Add the Graph permissions

    API permissions → Add a permission → Microsoft Graph → Application permissions

    Tick Mail.Read and Mail.ReadWrite, then Add permissions.

    Application, not Delegated

    Microsoft Graph offers Delegated and Application permissions on the same screen. Delegated means "acting as a signed-in user" and will not work here — nobody is signed in at 6am when the RFQ arrives. It must be Application permissions.

    Then click Grant admin consent for EDM Zone Limited and confirm. Adding the permissions is not enough on its own; without consent every request is refused. The status column should read Granted for EDM Zone Limited with a green tick against both rows.

  4. Restrict it to the one mailbox

    This step matters more than the rest. Graph application permissions are tenant-wide by default: as registered above, the app can read every mailbox in EDM Zone, not just sales@. Scoping it is what makes this safe.

    Microsoft's current mechanism is RBAC for Applications in Exchange Online. (The older New-ApplicationAccessPolicy approach still works but is legacy and is being retired — use this instead.)

    In Exchange Online PowerShell, connected as an Exchange administrator:

    # 1. Connect
Install-Module ExchangeOnlineManagement -Scope CurrentUser
Connect-ExchangeOnline -UserPrincipalName you@edmzone.co.uk

# 2. A scope containing only the sales mailbox
New-ManagementScope -Name "Quoting app - sales mailbox only" `
  -RecipientRestrictionFilter "PrimarySmtpAddress -eq 'sales@edmzone.co.uk'"

# 3. Register the app's service principal in Exchange.
#    AppId is the Application (client) ID from step 1.
#    ObjectId is the Object ID of the ENTERPRISE APPLICATION
#    (Entra ID -> Enterprise applications -> EDM Zone Quoting),
#    which is NOT the same as the app registration's object ID.
New-ServicePrincipal -AppId <application-client-id> `
  -ObjectId <enterprise-app-object-id> `
  -DisplayName "EDM Zone Quoting"

# 4. Grant the two roles, scoped to that mailbox only
New-ManagementRoleAssignment -App <application-client-id> `
  -Role "Application Mail.Read" `
  -CustomResourceScope "Quoting app - sales mailbox only"

New-ManagementRoleAssignment -App <application-client-id> `
  -Role "Application Mail.ReadWrite" `
  -CustomResourceScope "Quoting app - sales mailbox only"
    Please do not skip this

    Without step 4, a single leaked secret exposes every mailbox in the business — HR, finance, the directors — not just the sales inbox. With it, the blast radius is one mailbox that already receives mail from outside the company.

  5. Send three values back to Roger

    • Directory (tenant) ID — not secret
    • Application (client) ID — not secret
    • Client secret Value — this one is a password
    How to hand over the secret

    The client secret is equivalent to a password for the sales mailbox. Do not email it, do not put it in a chat message, and do not paste it into an AI assistant — anything typed into a chat window is stored in that conversation.

    Put it straight into the application's configuration file yourself, or hand it over through a password manager, or read it down the phone. The tenant ID and client ID are fine to send by ordinary email; they identify the app but grant nothing on their own.

What happens after that

  1. The three values go into the app's settings file (backend/.env) — never into the code, and never into a conversation.
  2. Running python -m scripts.check_graph walks the whole connection one step at a time and stops at the first thing wrong with a specific fix. It checks the settings, the sign-in, the mailbox, the RFQ category and the tagged mail, and it decodes Azure's error codes — so "wrong secret", "wrong tenant" and "expired secret" are told apart rather than all appearing as one failure.
  3. Adding --poll pulls anything already categorised RFQ straight into the app, with its drawings.
  4. Then the real test: does it read your drawings correctly? That is measured against 20–30 jobs you have already quoted, before anyone relies on it.
  5. Last comes hosting, so it checks the mailbox on its own overnight rather than when somebody presses a button. No point hosting something whose accuracy has not been judged yet.
If something does not work

Do not spend long on it. Send me whatever scripts/check_graph.py prints — it is written to say precisely which of the six ways this can go wrong has happened, and five of those otherwise look identical from the outside: no enquiries appear.
